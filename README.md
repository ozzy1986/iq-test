# IQ-тест — MVP веб-сервиса с подпиской

**Демо: https://iq.ozzy1986.com**

Рабочая воронка: лендинг → тест из 12 вопросов → paywall с превью отчёта → имитация оплаты → результат.
Результаты и статус подписки хранятся на сервере в PostgreSQL, интерфейс — mobile-first.

Оплата — имитация: платёжного провайдера нет, карта не запрашивается, деньги не списываются.

## Воронка

| # | Экран | Что происходит |
|---|-------|----------------|
| 1 | Landing | Оффер, «12 вопросов / ~10 минут», одна кнопка. Цена подписки названа сразу, до начала теста |
| 2 | Quiz | Один вопрос на экран, прогресс, крупные варианты ответа, можно вернуться назад. Каждый ответ сразу сохраняется на сервере |
| 3 | Анализ | Короткий экран «проверяем ответы» (2–3 секунды) |
| 4 | Paywall | Превью отчёта без цифры IQ, состав отчёта, цена и условия подписки обычным шрифтом |
| 5 | Checkout | Сводка заказа, email, пометка «демо-режим», кнопка «Оплатить» → успешный mock-платёж |
| 6 | Result | IQ, уровень, процентиль на кривой распределения, профиль по 4 навыкам, выводы, разбор всех вопросов, управление подпиской |

Адрес прохождения — `/t/<uuid>`. Экран определяется состоянием на сервере, поэтому обновление страницы,
закрытие вкладки или открытие ссылки на другом устройстве возвращают ровно туда, где человек остановился
(в том числе на оплаченный отчёт).

## Конкуренты и выводы

Смотрел три типа сервисов:

- **Подписочные с trial** (класс MyIQ / TrueIQ). Тест бесплатный, после него — paywall. Доступ к результату
  продаётся как дешёвый пробный период, который затем превращается в заметно более дорогую подписку;
  условия продления написаны мелко. Конверсия в первую оплату высокая, но на этом же строится основной
  поток жалоб и возвратов.
- **Разовая покупка отчёта** (класс IQTest.com). Результат или расширенный отчёт продаётся один раз.
  Честнее, но выручка на пользователя ниже и нет повторных платежей.
- **Бесплатные** (класс International IQ Test). Результат отдают сразу, зарабатывают на сертификатах и
  дополнительных отчётах. Доверие высокое, монетизация слабая.

Что взято: paywall сразу после теста (момент максимальной мотивации), экран «анализа» перед ним,
подписочная модель, развёрнутый отчёт как предмет продажи.

Что сделано иначе:

- **Цена известна до старта.** На лендинге одной строкой сказано, что отчёт платный и сколько он стоит.
  Человек не тратит 10 минут, чтобы потом почувствовать себя обманутым.
- **Превью вместо пустого экрана.** На paywall видно, из чего состоит отчёт, и что результат уже посчитан;
  сама цифра и профиль закрыты.
- **Никакого trial-подвоха.** Одна цена, период и правило продления написаны тем же шрифтом, что и остальное.
- **Отмена в один клик** прямо на странице результата. Доступ сохраняется до конца оплаченного периода.
- **Платный отчёт — не одна цифра.** Профиль по навыкам и разбор каждого вопроса с объяснением дают
  ощущение, что деньги заплачены за содержание.

## Технические решения

```
Браузер → Apache (TLS) ─┬─ /      → статика SPA (React + Vite + TypeScript)
                        └─ /api   → FastAPI (uvicorn, systemd) → PostgreSQL
```

- **Backend:** Python, FastAPI, SQLAlchemy 2 (async), PostgreSQL. Локально по умолчанию — SQLite-файл.
- **Frontend:** React 19 + Vite + TypeScript, без UI-библиотек и роутера; фигуры в вопросах рисуются в SVG из данных.
  Шрифт Onest лежит на своём домене — сторонних запросов нет.
- **Деплой:** релизы в `releases/<метка>` + симлинк `current`, healthcheck и автооткат (`deploy/deploy.sh`).

Что важно для платного продукта:

- Правильные ответы, сложность и пояснения **не уходят на клиент** — в ответе API их нет.
- Подсчёт выполняется на сервере. Эндпоинт завершения теста **не возвращает результат** — только превью.
- `GET /result` отдаёт отчёт только при действующей подписке, иначе `402`. Обойти paywall правкой фронтенда нельзя.
- Повторный запрос оплаты не создаёт второй платёж; после завершения теста ответы изменить нельзя.
- Идентификатор прохождения — UUIDv4, он же служит ключом доступа (аккаунтов в MVP нет).
- Лимит запросов по IP (создание теста, ответы, оплата, события) и отказ от тел больше 4 КБ до их чтения.
- Строгий CSP без сторонних источников, HSTS, запрет встраивания во фреймы; API слушает только localhost.
- Платёжный провайдер спрятан за протоколом (`app/payments.py`): настоящий подключается без правок API.

### Данные

| Таблица | Содержимое |
|---------|------------|
| `sessions` | прохождение: ответы, балл, IQ, процентиль, разбивка по навыкам, email |
| `payments` | платёж: сумма, валюта, провайдер (`mock`), статус |
| `subscriptions` | тариф, статус (`active` / `canceled`), начало и конец оплаченного периода |
| `events` | шаги воронки для расчёта конверсий |

### API

| Метод | Назначение |
|-------|------------|
| `GET /api/plan` | тариф и число вопросов — единственный источник цены для интерфейса |
| `POST /api/sessions` | начать тест; возвращает вопросы без ответов |
| `GET /api/sessions/{id}` | текущее состояние (для восстановления после перезагрузки) |
| `PUT /api/sessions/{id}/answers/{question_id}` | сохранить ответ |
| `POST /api/sessions/{id}/finish` | посчитать результат на сервере; в ответе только превью |
| `POST /api/sessions/{id}/checkout` | имитация оплаты → платёж `succeeded`, подписка `active` на 30 дней |
| `GET /api/sessions/{id}/result` | полный отчёт; `402`, если подписки нет |
| `POST /api/sessions/{id}/subscription/cancel` | отменить продление |
| `POST /api/events` | событие воронки с клиента |

Схема OpenAPI: https://iq.ozzy1986.com/api/openapi.json

### Подсчёт

Вопросы имеют вес 1–3 по сложности. Доля набранных баллов линейно переводится в шкалу 72–140,
процентиль берётся из нормального распределения N(100, 15). Это ориентировочная развлекательная оценка,
а не психометрический инструмент: для настоящей шкалы нужна нормировка на выборке.

### Конверсия по шагам

```sql
select name, count(distinct coalesce(session_id, id::text)) as users
from events group by name
order by array_position(array['landing_view','quiz_start','quiz_finish','paywall_view',
                              'checkout_view','payment_success','result_view','subscription_cancel'], name);
```

## Запуск локально

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt        # Linux/macOS: .venv/bin/pip
.venv/Scripts/python -m uvicorn app.main:app --port 8130
```

```bash
cd web && npm install && npm run dev                  # http://localhost:5173, /api проксируется на :8130
```

Без `DATABASE_URL` используется SQLite (`dev.db`). Для PostgreSQL:
`DATABASE_URL=postgresql+psycopg://user:pass@127.0.0.1:5432/iq`.

Тесты: `pip install pytest httpx && python -m pytest tests` — сквозной сценарий воронки через API
(утечка ответов, paywall, отказ платежа, лимиты) и модульные тесты подсчёта и правила доступа.

### Ограничения MVP

- Один процесс API; лимит запросов хранится в его памяти. Для нескольких воркеров счётчики нужно вынести в Redis.
- Таблицы создаются через `create_all`, без миграций.
- Автотестов интерфейса нет: фронтенд проверялся вручную на ширине 375 px и на десктопе.
- Шкала IQ не нормирована на выборке.

## Идеи для развития

**Монетизация**

- A/B-тест модели: подписка против разовой покупки отчёта. Для одного теста разовая покупка честнее
  и может дать лучшую выручку за вычетом возвратов; подписка оправдана, когда есть регулярная ценность.
- Регулярная ценность для подписки: новые тесты (память, внимание, EQ), ежедневные тренировки,
  динамика результата во времени — тогда продление перестаёт быть «забытым списанием».
- Годовой тариф со скидкой и лестница цен на paywall; региональные цены.
- Допродажи после оплаты: именной PDF-сертификат, расширенный отчёт.
- Напоминание за 3 дня до списания — снижает возвраты и чарджбэки сильнее, чем теряет продлений.

**UX и конверсия**

- Email до paywall («куда прислать результат») — возможность дожимать тех, кто не оплатил.
- Сравнение с друзьями: ссылка-вызов «пройди и сравни» — бесплатный виральный канал.
- Адаптивная сложность: следующий вопрос подбирается по предыдущим ответам, тест короче при той же точности.
- Таймер на вопрос и учёт скорости в оценке; больше визуальных матриц.
- Локализация: воронка одинаково работает на любом рынке.

**Техника**

- Реальный провайдер (ЮKassa / Stripe) с вебхуками вместо mock; подпись вебхуков и идемпотентность по ключу.
- Аккаунт по magic-link на email: восстановление доступа и личный кабинет.
- Миграции Alembic вместо `create_all`; общий стор для лимитов и несколько воркеров; e2e-тесты интерфейса (Playwright).
- Нормировка шкалы на собственных данных, когда наберётся выборка.
